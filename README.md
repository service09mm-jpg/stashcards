# StashCards

Картки лояльності, що завжди під рукою — навіть без інтернету.

Відкривається з іконки на домашньому екрані, показує штрихкод за два дотики
й не звертається до мережі взагалі. Ніякого бекенду: номери карток не
залишають телефон.

## Що всередині

| Шар | Рішення | Чому саме так |
| --- | --- | --- |
| Каркас | Vite + React + TypeScript | статична збірка без сервера, яка цілком поміщається в кеш браузера |
| Оформлення | Tailwind CSS | |
| PWA | `vite-plugin-pwa` (Workbox) | манифест і service worker, який кладе весь застосунок у precache |
| Сховище | IndexedDB через Dexie | єдине браузерне сховище, що тримає фотографії й не має ліміту в кілька мегабайтів |
| Штрихкоди | `bwip-js` | малює 13 форматів на самому пристрої, у SVG |
| Сканування | `BarcodeDetector`, запасний — `zxing-wasm` | системний декодер там, де він є (Android); wasm там, де його немає (iOS) |
| Хостинг | Vercel | статика на CDN |

## Команди

```bash
npm run dev       # застосунок у режимі розробки (service worker увімкнено)
npm run build     # збірка для проду
npm run preview   # подивитися зібране
npm run lint
npm run test      # модульні тести (Vitest)
npm run test:e2e  # наскрізні тести (Playwright), разом із перевіркою офлайну
npm run icons     # перемалювати іконки застосунку
```

## Порядок карток

Порядок задає юзер: притримайте плитку й перетягніть. Більше ніщо його не
змінює — ані відкриття картки, ані частота використання.

Так було не завжди: спершу список сортувався сам, за останнім використанням.
Ідея виглядала розумною, а на практиці виявилася гіршою за сталий порядок —
список, який щоразу має інший вигляд, доводиться перечитувати очима, тоді як
сталий запам'ятовується рукою.

Нові картки стають у кінець, щоб не зсувати вже розставлене. Порядок
потрапляє і в резервну копію.

Утримання потрібне, щоб не заважати гортанню списку: доки палець не
затримався на картці, жест лишається звичайним гортанням. Перетягування
перевіряється справжніми дотиками, а не мишею, — на миші воно працює й тоді,
коли на телефоні не працює зовсім.

## Як це працює офлайн

Service worker кладе в кеш усі файли застосунку одразу після першого
відкриття, тож далі він запускається без жодного мережевого запиту. Самі
картки лежать в IndexedDB, а штрихкод малюється на пристрої в момент показу —
ні за даними, ні за картинкою нікуди звертатися не треба.

Перевірка цього не на словах: `e2e/offline.spec.ts` вимикає мережу,
перезавантажує сторінку й переконується, що картка відкривається, а нову
можна додати.

## Що варто знати про iOS

- Встановлення тільки руками: Safari → «Поділитися» → «На екран «Додому».
  Apple не дає сайту жодного способу запропонувати це самому, тому в
  застосунку є текстова підказка.
- Доки застосунок не доданий на домашній екран, Safari має право вичистити
  його дані після довгого невикористання. Додавання виводить його з-під
  цього правила.
- Видалення іконки стирає картки остаточно. Тому експорт у «Налаштуваннях» —
  не додаткова можливість, а обов'язкова частина: без копії дані втрачаються
  назавжди.
- Камери в сканері немає до iOS 16.4 — там лишається ручне введення коду.

## Резервна копія

«Налаштування» → «Зберегти» кладе всі картки разом із фотографіями в один
файл JSON. «Відновити» вливає його назад; картки зіставляються за
ідентифікатором, з двох версій лишається новіша, тому вливати копію можна
скільки завгодно разів і на скількох завгодно пристроях.

Синхронізації між пристроями поки немає, але дані до неї готові: кожна
картка має власний UUID, час останньої зміни й позначку видалення — саме те,
з чого вона будується.

## Тести в середовищі з власним Chromium

Якщо браузер уже встановлено в системі й завантажувати копію нікуди
(контейнери, CI без доступу до мережі):

```bash
CHROMIUM_PATH=/шлях/до/chrome npm run test:e2e
```

Без цієї змінної Playwright бере браузер, поставлений через
`npx playwright install`.

## Розгортання

Усі параметри збірки закріплені у `vercel.json`, а не в налаштуваннях
проєкту на Vercel: пресет `vite`, команда `npm run build`, результат у теці
`dist`. Файл має пріоритет над дашбордом, тож змінювати там нічого не треба —
і випадково виставлений Output Directory більше не ламає розгортання.

Крім збірки, `vercel.json` робить дві речі: віддає `index.html` на будь-яку
адресу (маршрути живуть у браузері) і забороняє довго кешувати `sw.js` —
інакше нова версія застосунку не доїхала б до вже встановлених копій.
